# Админ-панель

Адрес: `/admin_panel`. Панель работает на Symfony + Twig без отдельного frontend-приложения. Вход закрыт паролем, формы защищены CSRF, попытки входа ограничены. Панель не индексируется и не кешируется.

## Создать администратора

После миграций:

```bash
# Development
docker compose exec backend php bin/console admin:user:create admin@example.com

# Production
bash scripts/prod.sh exec backend php bin/console admin:user:create admin@example.com
```

Команда запросит пароль и повторное подтверждение скрытым вводом. Минимум 8 символов; email нормализуется в нижний регистр. Пароль хранится как хеш Symfony PasswordHasher. Существующая учётная запись не перезаписывается. Публичной регистрации нет.

Для автоматизации доступен `--password-stdin` с `--no-interaction`: передавать пароль через stdin из защищённого источника, не аргументом командной строки. Не сохранять действующие пароли в Git.

## Вендоры и модули

1. Нажать «Добавить модуль», в том числе внутри выбранного вендора.
2. Вставить ссылку на оригинальную страницу товара. При необходимости указать свою affiliate-ссылку.
3. Нажать «Загрузить модуль по ссылке». Название, описания, обложка, галерея, README / User Guide, цена в USD, рейтинг, возможности и совместимость извлекаются со страницы, когда эти данные там доступны. Фотографии скачиваются в локальное хранилище.
4. Новая карточка автоматически публикуется. Вендор берётся из выбранного раздела либо определяется по домену сайта; неизвестный вендор создаётся автоматически. Категория определяется по категории товара и хлебным крошкам источника, затем по названию, адресу и краткому описанию модуля. Нужная категория создаётся автоматически, если её ещё нет в каталоге. При отсутствии совпадения используется Other Extensions.
5. Повторная загрузка той же оригинальной ссылки обновляет карточку без дубля, сохраняя её адрес, публикацию и счётчики. Пустая affiliate-ссылка при повторном импорте не стирает существующую.

Все поля для ручной корректировки остаются в свёрнутом разделе «Ручная корректировка (необязательно)». Заполнять их для импорта не требуется.

### Affiliate-ссылки целого вендора

В «Настройках вендора» доступно поле «Affiliate-ссылка для модулей вендора». Оно применяется к существующим и новым модулям без индивидуальной affiliate-ссылки. Изменение общей настройки сразу меняет ссылки этих модулей; повторный импорт не нужен. Индивидуальная ссылка модуля имеет приоритет. Чтобы заменить её сразу у всех модулей выбранного вендора, установите флажок «Применить ко всем существующим модулям…» и сохраните вендора. Эта операция очищает индивидуальные ссылки, после чего модули используют общую настройку. Модули других вендоров не меняются. Пустое общее поле отключает наследование; массовая замена с пустым значением не допускается.

Поддерживаются:

- `?ref=your-id` — добавить партнёрские параметры к оригинальной ссылке каждого товара, сохранив параметры товара и fragment.
- `https://tracking.example/click?url={url_encoded}&ref=your-id` — подставить URL товара, закодированный для параметра партнёрской сети.
- `{url}` — подставить оригинальную ссылку без кодирования.
- Обычная полная HTTP(S)-ссылка — один общий адрес для всех модулей.

Общие ссылки используются и в публичном каталоге, и в переходах `/go/affiliate/…`; счётчики и индивидуальные настройки сохраняются при Upload. Перед развёртыванием обновлённого backend примените миграцию `008_vendor_affiliate.sql` командой `bash scripts/prod.sh run --rm --no-deps migrate` (стандартный `scripts/deploy.sh` применяет её автоматически).

При изменении цены установки в модуле учитывать цену услуги `services`: сумму заказа определяет backend по услуге. Непосредственно цены услуг управляются через текущий импорт/SQL; эта лёгкая панель предназначена для вендоров и модулей.

## Удаление

В карточках модуля и вендора есть кнопки «Удалить модуль» / «Удалить вендора». Они открывают отдельную страницу подтверждения. Удаление выполняется только после установки флажка и отправки формы с CSRF-токеном; открытие ссылки ничего не меняет.

- Модуль без заказов удаляется вместе со статистикой переходов. Модуль с заказами удалить нельзя: снимите флажок «Опубликовать в каталоге», чтобы сохранить историю заказов.
- Вендор удаляется, когда у него не осталось модулей. Сначала удалите модули или перенесите их к другому вендору через ручную корректировку.
- Восстановления удалённых записей в панели нет. Загруженные файлы не удаляются автоматически.

Перед использованием удаления на сервере примените миграцию `007_admin_catalog_delete.sql` обычной командой `bash scripts/prod.sh run --rm --no-deps migrate`. Она добавляет роли приложения право удаления только из `partners` и `extensions`.

## Upload

Импорт и Upload также автоматически формируют отдельные SEO title и description из метатегов оригинала и данных модуля. Они доступны в необязательном разделе SEO и не меняют название карточки. Подробнее — [SEO](seo.md). Для заполнения старых записей без повторного скачивания фото: `docker compose exec backend php bin/console app:seo:refresh`.

Кнопка у каждого добавленного модуля читает сохранённую оригинальную ссылку. Обновляются доступные название, описания, цена в USD, рейтинг (шкала нормализуется к 5), обложка, галерея, категория, возможности, совместимость и README / User Guide. Affiliate-ссылка, slug, вендор, публикация и счётчики сохраняются. Загрузка запускается вручную, после входа и с CSRF-токеном.

Поддерживаются JSON-LD / Open Graph, товарная разметка Magento, галереи Hyvä и Magento, HTML-слайдеры Mageworx (включая ленивую загрузку `data-src`), карусели PhotoSwipe Plumrocket, HTML-карусели Firebear, Fancybox-галереи Mageplaza, ссылки на руководства в HTML. Для Mageworx выбираются полноразмерные скриншоты; миниатюры используются, если полноразмерной галереи нет. Ссылки User Guide имеют приоритет над упоминаниями руководств в описаниях, ссылки из навигации и футера исключены. Импорт CCPA Amasty, Marketing & Sales Suite Mageworx и Social Login Pro Plumrocket и Improved Import & Export Firebear проверяется по настоящим страницам. Список скриншотов Plumrocket читается как JSON без выполнения JavaScript; видео не импортируются. За один импорт скачивается до 32 изображений; отсутствующие в источнике поля не выдумываются. Если фото или руководство недоступны, панель показывает предупреждение. Если сайт блокирует запрос или не отдаёт название/описание, импорт завершается ошибкой без создания пустой карточки. Ссылки на внутренние сети блокируются `NoPrivateNetworkHttpClient`. Иностранная валюта автоматически не переводится в USD.

Для Mageplaza галерея читается из основного слайдера `heroSlider`, без повторов из миниатюр и рекламных блоков. Рейтинг и отзывы извлекаются из JSON-LD даже при неэкранированных переносах строк внутри текстов; остальные ошибки JSON не исправляются. Возможности и совместимость с Hyvä берутся только из блока текущего товара. При нескольких редакциях ссылка User Guide указывает на первую редакцию (Standard); её можно заменить вручную. Старый шаблон Mageplaza также поддерживается: отдельные картинки основного слайдера и блок `mp-screenshots`. SVG-иконки и GIF пропускаются; обложкой становится первое поддерживаемое растровое изображение. Проверено на One Step Checkout с 28 изображениями и Ajax Layered Navigation с 7 растровыми изображениями.

Для Wyomind поддерживается HTML с глубоко вложенными отзывами: JSON-LD в конце страницы читается полностью, рейтинг и число отзывов берутся у модуля, а не у сайта в целом. Скриншоты и возможности читаются из `#overview`, включая картинки без lightbox-ссылки; рекламные блоки других модулей, GIF и миниатюры исключаются. User Guide ведёт на встроенное руководство `?section=documentation#userguide`, совместимость берётся только из `#compatibility`. Проверено на Simple Google Shopping: 5 PNG, 17 возможностей, рейтинг 4,9 и 545 отзывов. При загрузке Wyomind импорт автоматически запрашивает страницу с `c=usd`, сохраняя остальные параметры запроса и исходную ссылку карточки. Цена берётся из видимого блока товара только при выбранной USD в переключателе: JSON-LD Wyomind остаётся в EUR даже после переключения. Проверено на Simple Google Shopping: $164. Конвертация на нашей стороне не выполняется; если долларовая цена недоступна, сохраняется прежнее значение и показывается предупреждение. После обновления backend существующую карточку нужно обновить кнопкой Upload.

Общий импорт JSON-LD / Open Graph, Magento и Hyvä остаётся доступен для любого вендора. Особые правила Wyomind и повышенный лимит вложенности HTML применяются только к точным доменам `wyomind.com` и `www.wyomind.com`. При добавлении поддержки вендора проверяйте весь `php tests/importer.php` и `php tests/admin.php`, а не только новую страницу: тесты охватывают прежние шаблоны Mageworx, Plumrocket, Firebear, обе галереи Mageplaza, разметку Amasty, общие галереи Magento/Hyvä и неизвестный сайт. Дополнительно проверяется, что похожая разметка и похожие домены не включают правила другого вендора. Полный набор входит в `composer qa`. Проверки используют HTML-примеры и не гарантируют неизменность внешних сайтов: при смене их шаблона нужно обновлять соответствующие правила и примеры.

Для файлов с компьютера используются отдельные поля главного фото и скриншотов в форме модуля. Разрешены проверенные по содержимому JPG/PNG/WebP до 8 МБ на файл; SVG, HTML, PHP и архивы не принимаются. Имена генерируются сервером, расширения берутся из MIME. За один запрос — до 8 дополнительных скриншотов; общий размер запроса ограничен 40 МБ.

## Счётчики

- `/go/module/{slug}` увеличивает открытия карточки и перенаправляет на `/extension/{slug}`. Обложка и название модуля в каталоге используют обычные ссылки, без Next.js prefetch.
- `/go/affiliate/{slug}` увеличивает партнёрские переходы и перенаправляет на сохранённую affiliate-ссылку; если она пуста — на оригинал.
- HEAD-запросы не учитываются. Переходы не кешируются. Не сохраняются IP-адреса и cookie посетителей. Это счётчики обращений по ссылкам, не уникальные пользователи; боты и повторные клики могут их увеличивать.
- Счётчики хранятся отдельно от контента в `module_metrics`, обновляются атомарно и видны по каждому модулю и суммарно в панели.

## Docker и хранение

Миграция `005_admin_panel.sql` создаёт пользователей, статистику и поля оригинальной ссылки, публикации и времени обновления. Роль приложения получает только необходимые дополнительные права.

Карточки и галерея используют `next/image`: миниатюры, основной просмотр и увеличение получают разные размеры. Поддерживающим браузерам отдаётся WebP; для крупных скриншотов используется качество 85, для карточек и миниатюр — 75. Оригиналы не меняются. В production кеш оптимизированных файлов хранится в volume `frontend_image_cache` (лимит 512 МиБ), отдельно от оригиналов. Для локальных `/media/modules/` Next читает файлы через внутренний gateway, поэтому новые загрузки доступны без перезапуска. Внешние HTTPS-изображения также оптимизируются, HTTP-ссылки продолжают отображаться без оптимизации.

Нулевая цена модуля отображается как `FREE`, в том числе если импортированный тип лицензии остался `one-time` или `subscription`. Правило применяется в карточках, на странице модуля, в сравнении и фильтре бесплатных модулей; цена услуги установки не меняется.

Фотографии из панели хранятся в named volume `module_uploads`, монтируемом в PHP как `/app/var/storage` и в nginx только для чтения. Они сохраняются при пересборке/redeploy. Публичный путь — `/media/modules/`. Коммитить их в Git или пересобирать Next.js для загрузки нового фото не требуется.

Резервное копирование БД включает пользователей и статистику. Volume с фото нужно резервировать отдельно вместе с БД. Не выполнять `down -v` или удаление volumes. Обычные PHP-сессии завершаются при замене backend-контейнера — после deploy администратор входит повторно.

Для ручной корректировки категории выбираются из текущего каталога. Начальная категория Compliance & Legal уже создана миграцией; дополнительные категории можно добавить существующим JSON-импортом/SQL. Веб-редактор категорий и управление услугами в эту панель не входят.
