# Поиск в каталоге

Живой поиск на `/extensions` использует уже загруженный каталог. Изменение строки поиска и фильтров обновляет URL через нативный `history.replaceState`, поддерживаемый Next.js, и не запускает серверную навигацию с повторной загрузкой `/api/catalog`. Перезагрузка страницы и прямой переход по ссылке продолжают обрабатывать параметры на сервере для SEO и начальной выдачи. Оформление заказа использует прежнюю серверную навигацию.

Поле ввода подписано на синхронный снимок URL через `useSyncExternalStore`: обновления собственного поиска и `popstate` применяются сразу. Это предотвращает потерю символов при быстром наборе, которая возможна, если контролируемое поле напрямую зависит от отложенного обновления `useSearchParams`.

Общий компонент ссылок отключает автоматическую предзагрузку страниц по умолчанию. Сейчас каждый динамический маршрут содержит каталог; предзагрузка ссылок в новых результатах и попавшем в экран футере создавала дополнительные запросы каталога во время набора текста. Переход по нажатию работает как обычно; явный `prefetch` при необходимости может переопределить настройку компонента.

Поисковый текст из названия, краткого и полного описания, имени вендора и тегов нормализуется один раз на версию каталога. Последующие запросы переиспользуют индекс. При замене массива модулей или вендоров индекс перестраивается; исходные объекты не нужно изменять на месте. `WeakMap` позволяет освобождать старые индексы вместе с каталогами. Список тегов также вычисляется один раз при изменении каталога.

Фильтрация охватывает весь каталог, затем применяется сортировка и пагинация по 24 карточки. Поиск сбрасывает номер страницы на первую и сохраняет выбранные фильтры в URL.

Проверки: `npm test`, `npm run typecheck`, `npm run lint`. Тесты включают каталог из 2000 модулей, поиск по всем полям, повторное использование индекса и обновление данных. В локальном замере на 2000 модулях с длинными описаниями 110 последовательных запросов заняли около 45 мс с индексом против 582 мс при прежней нормализации на каждом запросе. Это замер вычислений, а не сетевого или браузерного времени; результаты зависят от устройства и данных.

Браузерная проверка production-сборки с 2000 тестовыми модулями: при последовательном и быстром наборе нет потери символов, дополнительных запросов каталога и RSC-страниц. Найден модуль с индексом 1999, номер страницы сброшен на первую. Сброс фильтров, прямой URL запроса и возврат со страницы услуг кнопкой «Назад» работают; ошибок JavaScript нет. Пройдены 26 тестов, типизация и lint (имеется прежнее предупреждение о подключении шрифтов в layout). Production-сборка проверена через webpack: Turbopack в локальной среде не смог открыть служебный порт.

Деплой: пересобрать frontend обычным способом. Изменений схемы БД и миграций нет. Первичная загрузка по-прежнему передаёт каталог целиком; переход на серверный поиск и компактный поисковый API — отдельный этап при дальнейшем росте каталога.
